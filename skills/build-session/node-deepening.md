# Node deepening

Load this file when a session's prep needs a node built to real depth — a
location central to tonight's play that the record can't run cold, or a seed
that has to become a page before the session can use it. It is a procedure,
not a door: nothing routes here on its own.

Deepening is the fractal campaign record's granularity move: a topic at low resolution — a seed section or a thin page — is promoted to a full node with its own internal web. Two branches share the steps below: **promote** (a seed section becomes a new page) and **deepen** (an existing underbuilt page is built out in place).

Before anything, read the campaign repo's own guide to its structure (`CLAUDE.md` or equivalent, and any planning-method handbook it points to). Every format convention this procedure touches — clue-web layout, link style, frontmatter, log entries — is owned by those docs, not by this file. This file enumerates *what* must be touched; the repo's docs say *how*. Where the docs don't resolve a convention this procedure needs, ask the DM inline and offer to record the answer in the campaign's own docs so the next run discovers it.

**Elaborate set dressing freely — decide nothing plot-relevant; bring every plot decision to the DM as a question.**

The authorship test: if the players could later discover a detail was retconned, it is plot — bring it to the DM as a question in prose, with a recommendation. If it is set dressing they would never notice changing, draft it. When the source seed is a single evocative line, pitch 2–3 directions before drafting anything.

## Steps

### 1. Gather
Locate the target (seed section or existing page) and read it. Then sweep the campaign record for every existing mention of it: inbound links and name references from other pages, promises made about this node in the live story layer (e.g. checklist clues marked "to be keyed when built" — **IOUs** this pass must honor), its placement in the macro-outline, and any open questions touching it.
**Done when:** every existing mention is found and read, and the IOU list is written down.

### 2. Pitch
Sort what the page needs into *decided* (canon already says), *set dressing* (draft it), and *plot* (ask). Present the plot-tier questions to the DM before drafting. Anything the DM defers, park in the repo's open-questions tracking and mark *(undecided)* on the page rather than inventing an answer.
**Done when:** every plot-tier question is ruled on or explicitly parked.

### 3. Draft
Write the page (promote) or the new material in place (deepen). Ground invented things in the concrete real-world place or feature the node is named for, not an abstract theme. Give a location node a **focal monument** — one central physical feature scenes at the node can stage around (a fountain, a defaced statue, a burned-out sign) — tied to a faction, figure, or event the campaign already establishes, so the place carries a texture of history and the feature can anchor a clue if the web ever wants one there; where the place honestly doesn't support one, don't force a centerpiece on a node whose texture is its plainness. The tie is set dressing; deciding what it *reveals* stays plot-tier. Clue *content* lives in the body under its own headings; the clue-web section only indexes it. Any clue or lead written here must be interpretable using only what the players already know when they could plausibly find it — a clue may gain meaning later, but must never require unseen content to mean anything at all — and must carry a player-reachable vehicle: a concrete scene, action, check, or bargain yields it. A fact stated in DM-facing text with no way for the players to obtain it is not a placed clue.
**Done when:** the page reads as a durable situation — more material than one session consumes, and no scripted sequence of events.

### 4. Wire
Two directions. **Outbound:** the node's clue-web section indexes its leads to other nodes. **Inbound:** the node must be reachable — at least one lead from an already-built node points here. Inbound placement is plot-adjacent (someone or something must plausibly carry the clue), so propose placements and edit the other pages only after the DM's nod. Key every IOU from step 1 in the live checklist. If the node could support revelation coverage nobody promised, flag the opportunity — don't seed it.
**Done when:** outbound leads indexed, at least one inbound lead placed, every IOU keyed or explicitly rejected.

### 5. Bookkeep
Complete every item, or mark it N/A with the reason:
- [ ] Frontmatter matches the page's directory and status conventions
- [ ] Clue-web section present with its glance line (even if leads are few)
- [ ] *(promote)* Seed section deleted from its seed-ideas file
- [ ] *(promote)* The repo's page catalog updated
- [ ] Macro-outline: node enrolled in its scenario group, and the group's map updated per the repo's drawing rules
- [ ] Live status layer updated wherever this node changed it (checklist anchors, thread lines)
- [ ] Operation log entry written

If the repo's docs name a bookkeeping obligation this list lacks, do it and flag the gap so this list can be fixed.
**Done when:** every box checked or N/A-with-reason.

### 6. Verify
Re-walk the done-lists of steps 4 and 5 against the actual files, not from memory. Then offer two closers: an integrity-audit pass (worthwhile after a batch of deepenings rather than every one), and — for a new location or NPC — an illustration via the repo's art skill, if one is installed.
**Done when:** the re-walk finds nothing; closers offered.
